## 一、为什么要按"芯片协议"分组

国产游戏鼠标很少自己写协议，多数**贴牌同一颗芯片**。所以按芯片分组比按品牌分组更省事：
一颗芯片的协议写好，那一整片贴牌厂商都能用。

## 二、通用基础：怎么找设备、怎么传输

### 找设备：HID 用法页是关键

同一个鼠标会暴露**多个 HID 集合**，电量只在其中一个上。用 `(VID, PID, 用法页, 可选用法, 接口号)` 能唯一定位。

- VID = 厂商号（USB 官方分配）
- PID = 产品号（同一型号的**无线接收器**和**有线直连**通常是两个不同 PID）
- **用法页（usage page）**：非标准值（`0xFF01`、`0xFF02`、`0xFF05`、`0xFFFF` 等）就是厂商自定义集合的"门牌号"

### 传输方式：两种

| 方式 | 用法 | 特点 |
|---|---|---|
| **feature report** | `send_feature_report` 发，`get_feature_report` 收 | 主动问答；Lamzu / Ninjutso / Razer / Bloody 用这个 |
| **interrupt report** | `write` 发，`read` 收 | Nordic 用这个；AttackShark / MCHOSE 更特殊——鼠标**自己主动推送**，不用发命令 |

### 三种"收不到"的含义要分清

读不到电量不一定是"没鼠标"，可能是：
- **鼠标睡了**（接收器在线但鼠标不回话）——罗技、Nordic 都会这样
- **有线直连**（走线时不走无线链路，某些协议根本不推电量）
- **接收器没插鼠标**（Bloquent 接收器会回 `255` 表示"无射频连接"）

## 三、各协议的事实数据

### 1. Nordic 52840（ATK / VXE / VGN / Zaopin / Scyrox / 达尔优 / G-Wolves）

**17 字节**请求/回复，报告 ID `0x08`，第 2 字节是子命令。

```
写: 08 04 00 00 00 00 00 00 00 00 00 00 00 00 00 00 49
读: 08 04 00 00 00 02 23 00 0e 94 00 00 00 00 00 00 82
    ^ID ^子命令              ^状态 ^%  ^有线 ^电压(mV)    ^校验
```

- 子命令 `0x04` = 电量查询
- 偏移 6 = 电量百分比（上例 `0x23` = 35%）
- 偏移 7 = 有线标志（0=无线，1=插线）
- 偏移 8-9 = 电压（小端，毫伏；上例 `0x0e94` = 3732 mV）
- **校验和：17 字节全部相加后 mod 256 = `0x55`**（所以固定请求末尾是 `0x49` = 73）
- HID 用法页 `0xFF02`、用法 `0x02`

### 2. Nordic 54L15（ATK Zero）

**64 字节**，报告 ID `0x08`，命令 `0x72`，HID 用法页 `0xFF05`、用法 `0x01`。

```
写: 08 7D 72 02 00 00 07 01 00 ...
读: 08 72 00 3A 00 07 01 64 16 11 00 ...
    ^ID ^命令 ^状态^长度      ^%  ^电压(mV 小端)
```

- 偏移 2 = 命令 `0x72`；偏移 6 = 子索引 `0x07`（电量）
- 回复偏移 2 = 状态（`0`=鼠标回答，`1`=没回答→睡了）
- 回复偏移 7 = 电量（`0x64` = 100%）
- 回复偏移 8-9 = 电压（小端；`0x1116` = 4374 mV）**仅插线时有效**，无线时是垃圾值
- **链路索引（偏移 5）关键**：`0` = 有线，`1` = 无线接收器。填错设备要么不回、要么回旧数据（状态=1）
- 子索引 `0x08` = 充电状态（`0x02` 插线 / `0x00` 未插）——**但接收器只转发 `0x07` 电量查询**，其余无线时不可用
- 接收器出厂和鼠标配对，PID 随配对通道变，同一型号鼠标可能配不同接收器（各需一行）

> **⚠️ 有线模式待验证**：原始出处 `Fan4Metal/ATK_tray` 的实现**在有线模式下直接返回 None**（`get_battery_2` 里遇到 `wired=True` 就跳过），理由是"有线回复不可靠"。
> 我们目前的实现**照读偏移 7**（和无线一样）。两种写法谁对，**只有真有 ATK Zero 插线测一次才知道**。以后有硬件时重点测：插线后偏移 7 是不是还是电量百分比。

| 型号 | VID | 无线 | 有线 |
|---|---|---|---|
| ATK Zero（接收器 L1） | `0x373B` | `0x1155` | `0x1154` |
| ATK Zero（接收器 L0） | `0x373B` | `0x124F` | `0x1154` |

### 3. RealTek（MCHOSE）—— 鼠标主动推送

**不是问答**，鼠标每隔 ~2 秒主动推一条**输入报告**。HID 用法页 `0xFF01`、用法 `0x01`。

- 推送报告 ID `0x13`，子类型 `0x1d` = 电量
- **所有负载字节都 XOR `0xFF`**（解码时再异或一次）
- 解码后偏移 5 = 电量百分比（`0x5d` = 93%）
- 解码后偏移 4 = 有线标志（1=插线，0=无线；偏移 2 是镜像）
- 用 vendor feature report `0xf9`（`11 f9 ff ff ...`）可以"催"一下让它推，但**特征报告读取不可靠**（返回上一次的缓冲），所以只能等推送
- 有线直连换 PID 但同一 vendor 集合，解码后偏移 4 变 1

| 型号 | VID | 无线 | 有线 |
|---|---|---|---|
| MCHOSE L7 Pro | `0x5253` | `0x1020` | `0x00B0` |

### 4. Attack Shark（Beken/Feeling）—— 鼠标主动推送

**不发任何命令**，只等推送。HID 用法页 `0x000A`、接口 2。

5 字节报告，ID `0x03`（所有异步事件共用这个 ID）：

```
03 DD EE P1 P2
^事件^设备^事件^参数1 ^参数2
      id  码
```

- 事件码 `0x40`（或 `0x41`）= 电量事件
- `P1`（偏移 3）= 充电状态（1=充满，2=已满，3=充电中；但**X3 上这个字节一直不变**，所以不能只靠它）
- `P2`（偏移 4）= 电量级别
- 设备 ID = 型号标识（不是厂商，VID/PID 多型号共用）：X3 `0x4D`、X11 `0x55`、R1 `0x10`、X6 `0x85`、X11 Pro `0xBE`、X11 SE `0x07`
- **电量解读有争议**：文档说 `P2` 是百分比（`0x64`=100%），但某次抓包读到的是**十位档**（`0x07`→70%、`0x0a`→100%）。该抓包已丢失无法复核，**加新型号前先用真实电量验证一次**
- 有线直连时**根本不推电量**，只能报"充电中、不知道多少"
- X11 首次上电可能先报 `0x64`（100%），真值随后到

| 型号 | VID | 无线 | 有线 |
|---|---|---|---|
| Attack Shark X3 | `0x1D57` | `0xFA60` | `0xFA61` |

### 5. A4Tech Bloody 8K 接收器

**不是经典 Bloody 协议**（那个是 VID `0x09DA`），这是 8K 接收器的独立固件，VID `0x1956`。**没有任何公开文档**，全部来自 USB 抓包。

两个 HID 接口：
- **接口 2**（用法页 `0xFF02`）：命令通道，发 8 字节 **feature report**（报告 ID 0）
- **鼠标接口**（用法页 `0xFF01`、用法 1）：状态通道，收 8 字节 **input report**（报告 ID `0x06`）

**命令**（feature report，报告 ID 0 在前）：

```
ping:  00 80 00 00 00 00 00 00 7f   "你在吗"，重复到鼠标回答
query: 00 80 ff 00 00 00 00 00 80   "吐状态"，回一串 06 xx 报告
```

（不知道 `query` 能否跳过 `ping`，所以两条都发，间隔 ~13ms）

**电量回复**（那一串里的 `06 56` 行）：

```
06 56 PP CC 00 00 00 00
^ID ^子^电量 ^有线
     类型
```

- 子类型 `0x56` = 电量；偏移 2 = 电量百分比；偏移 3 = 有线标志
- 串里其它子类型（`0x55`/`0x81`/`0x87`）是链路/DPI/回报率，忽略
- 鼠标**只在插拔时**主动推一次 `06 56`，平时不推 → 所以必须主动问
- 有线直连换 PID，接收器空着会回 `06 56 FF`（电量 255 = 无射频连接）→ **跳过 255，别当成"鼠标没了"**

| 型号 | VID | 无线 | 有线 |
|---|---|---|---|
| Bloody SG5 Pro | `0x1956` | `0x3069` | `0x3144` |

### 6. Lamzu

### 8. Razer

经典 OpenRazer 报告：**90 字节** payload，头部选命令类 `0x02` / 命令 id `0x07`，末尾 XOR 校验。旧工具用 pyusb 控制传输，其实就是 **feature report ID 0** 的 SET/GET_REPORT，用 hidapi 也能做（不用 libusb）。

```
请求 = [报告ID 0] + [0x1F, 0,0, 0x02, 0x07, 0x80, ...80字节..., XOR校验, 填充]
        ^事务ID     ^命令类 ^命令id
```

- **事务 ID（偏移 1）** = `0x1F`；只有用这个 ID 的机型才匹配（老家族用 `0x3F`/`0xFF`，需要改）
- 电量回来是 0-255，除以 255 × 100 换算成百分比
- **这个查询不返回充电状态**；睡眠的鼠标报 0
- PID 对照来自 OpenRazer 的 `razermouse_driver.h`

## 四、实现路线（自己写，不用它的代码）

### 最小可用（"先解决有没有"）

1. **Nordic 52840 协议**——一颗芯片覆盖 13 个型号，性价比最高
2. 在 `app/mouse.py` 里加一个 `read_nordic52(vid, pid)` 分支，复用现有的 `_Dev` 传输层（写/读 + 超时）
3. 加一张 `NORDIC52_MODELS` 表（VID, 无线 PID, 有线 PID, 显示名）
4. `read_battery()` 先按"罗技"匹配（`vid_046d`），否则按 Nordic 表匹配

### 再加（"再解决好不好"）

- **Razer**：OpenRazer 报告，但只有 `0x1F` 那批机型，老家族要改事务 ID
- **主动推送型**（MCHOSE / AttackShark）：要改成"打开集合等推送"，和现有的问答式不同，单独一条路径

### 需要实物才能验证的

**每加一个品牌/型号都要有那只鼠标在手。** 协议字节可能对，但接收器 PID、用法页这些细节不实测就写不准。你现在手上是 Logitech Lift，所以**国产/雷蛇这批一个都验不了**——等你有对应鼠标的实物再做。
